## Prerequisites

### Enable Workers for Platforms

To enable Workers for Platforms, you need to purchase the [Workers for Platforms Paid plan](/cloudflare-for-platforms/workers-for-platforms/reference/pricing/).

1. Go to **Workers for Platforms** in the Cloudflare dashboard.

   <DashButton url="/?to=/:account/workers-for-platforms" />

2. Complete the payment process for the Workers for Platforms Paid plan.

If you are an Enterprise customer, contact your Cloudflare account team to enable Workers for Platforms.

### Learn about Workers for Platforms

Refer to [How Workers for Platforms works](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/) to learn more about Workers for Platforms terminology and architecture.

---

This guide walks you through setting up Workers for Platforms. You will configure a [dispatch namespace](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dispatch-namespace), a [dynamic dispatch Worker](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dynamic-dispatch-worker), and a [user Worker](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#user-workers) to test a request end to end.

### 1. Create a dispatch namespace

A [dispatch namespace](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dispatch-namespace) is a collection of user Workers that your dispatch Worker can invoke using `env.DISPATCHER.get("worker-name")`.

By default, Workers in a namespace run in [untrusted mode](/cloudflare-for-platforms/workers-for-platforms/reference/worker-isolation/), which provides complete isolation between customer Workers. This prevents cross-tenant data access and is recommended when your customers control the code being deployed.

1. Go to **Workers for Platforms** in the Cloudflare dashboard.

   <DashButton url="/?to=/:account/workers-for-platforms" />

2. Select **Create namespace**.
3. Enter a namespace name (for example, `production`).
4. Select **Create**.

### 2. Create a dynamic dispatch Worker

A [dynamic dispatch Worker](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dynamic-dispatch-worker) routes incoming requests to user Workers in your namespace.

1. In your namespace, select **Create** > **Path-based Dispatch Worker**.
2. Enter a name for your dispatch Worker.
3. Select **Deploy**.

The dynamic dispatch Worker is created with the dispatch namespace binding pre-configured. This template routes requests based on URL path. For example, a request to `example.com/customer-1` routes to the user Worker named `customer-1` in your namespace.

To route requests based on subdomain, hostname, headers, or other criteria, refer to [Dynamic dispatch Worker](/cloudflare-for-platforms/workers-for-platforms/get-started/dynamic-dispatch/) for more routing patterns and examples.

### 3. Upload a user Worker

[User Workers](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#user-workers) contain the code your end users (customers) write. Upload a test Worker to verify your setup.

1. In your namespace, select **Create** > **Worker**.
2. Enter a Worker name (for example, `customer-worker-1`).
3. Choose the **Hello World** template.
4. Select **Deploy**.

In production, you will deploy user Workers programmatically using the API or SDK rather than the dashboard. This allows your platform to automatically deploy code on behalf of your customers. Refer to [Platform examples](/cloudflare-for-platforms/workers-for-platforms/platform-examples/#api-examples) for API and SDK examples.

### 4. Test the setup

Send a request to your dynamic dispatch Worker. The dynamic dispatch Worker routes the request to the user Worker, which returns the response.

Visit your dynamic dispatch Worker URL with the user Worker name in the path:

```txt
https://<dispatch-worker>.<your-subdomain>.workers.dev/customer-worker-1
```

You should see the response from your user Worker (`customer-worker-1`).
